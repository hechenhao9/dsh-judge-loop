# judge-loop：为项目产出成品

## 一句话

**教授定标准，导师做到位，成品直接交出去。** 没有闸门，没有 final/ 目录，没有退出码。

标准是 95 分，不是 100。95 的含义是「发出去不会被问倒」；再往上那 5 分，是把时间花在没人看的地方——用户要的是能用的东西，不是一个 100 分。

## 为什么必须两个人

一份东西能到多高，**上限在标准，不在写的人**。

这个技能最早的版本是我自己写标准、自己写稿、自己打分——标准里清清楚楚印着稿子的四个特征（词数区间、停顿符号、卖点后跟路径、可整段复制）。出题人和考生是同一个人，那个 100 分是我给自己盖的章。

拆成两个角色，只解决一件事：**写标准的人不能是写稿的人。**

| 团队 | 干什么 | 不许干什么 |
|---|---|---|
| **教授**（`professor`） | 只读题目与素材，产出 `rubric.json` | 不许看导师的任何一版稿；不许在标准里写「参考稿是这样」 |
| **导师**（`tutor`） | 按标准写到 95 分以上 | 不许改 `rubric.json`；不许自己加判据 |

导师遇到读不懂的判据，可以问教授**三件事**：这条的初衷是什么、它在防哪种稿、满分的样子长什么样。**不许问「怎么写才能过」**——那是让教授代写。

## 流水线

```
题面 + 素材
   ↓  教授（不看稿）
rubric.json          4–6 维，合计 100，合格线 95
   ↓  导师（可问初衷，不许问写法）
draft-v1.md          自评：每维 0/4/7/10，quote 抄稿里逐字存在的原文
   ↓  只改掉分项的句子，且必须删一处
draft-v2.md          自评 ≥95 → 交给独立判分人
   ↓  外部判分（不是你、不是导师）
   ↓  ≥95 且无硬否决
交付
```

目录就三个东西，不需要更多：

```
<work>/
  rubric.json      教授产出，导师不许改
  draft-v1.md      第一版 + 自评
  draft-v2.md      改后版本
  blocked.md       只在卡住时出现（见最后）
```

## 95 分怎么算

六个维度不是都要 10。**允许一维是 7，其余满分就是 95 左右**——这对一份真实交付是对的：总有一处你只能做到「够用」，那不影响它能不能发出去。

算账很直接：某维权重 w，从 10 掉到 7，总分 = 100 − 3w/10。

- w=20 → 94（差一点，得再修一处）
- w=15 → 95.5（过线）
- w=10 → 97（过线，说明这一维不关键）

**所以：低权重的维度可以掉档，高权重的不行。** 判分时照这个算，不用纠结「看起来差不多」。

四条红线不看分数，命中就不许交：

1. **数字/引文编造**——凡引用素材，必须能指出哪个文件哪一行，翻得到。
2. **拿立场当事实**——没有来源的判断句可以留，但要写成立场（"我看这一单不值得接"），不许写成事实（"这个行业普遍如此"）。
3. **两份材料自相矛盾**——同一件事在两处说法不同，读者第一眼就会问。
4. **答应了自己做不到的**——没有的能力、没有的案例、没有的人。

## 判据要好到能用

教授写 `rubric.json` 时，每一维必须有：

- `criterion`：≥12 字，**且含一个能被外部抽查的对象**——路径、文件名、行号、数字、原文片段、命令。写「有深度」是空话。
- `pass_example` / `fail_example`：各一个具体样子，必须不同。写不出两个样子，说明这条只是形容词。
- `intent` / `vision`：这条在防哪种稿、满分长什么样。**导师就靠这两行理解标准。**
- `weight`：10–30。

外加 `vetoes` 至少一条：什么情况下分数再高也不能交。

标准写完之后自检一句：**把它单独发给一个只看过题目、没看过稿的人，他能不能明白为什么这一条必须存在？** 不能，就是这条写坏了。

## 反复出现的四类失分（照这个查）

| 症状 | 长什么样 | 怎么改 |
|---|---|---|
| 结论比素材硬 | 素材说「高于 25% 会搬到中越」，稿子写成「两国成本一样」 | 回到素材的原话，条件、限定词、时态一个不许丢 |
| 一句话两件事，对一错一 | 「A 是真来源，B 是我推的」混在同一句 | 拆成两句，把推的那句标成立场 |
| 引文是转述不是原文 | 引用时换了同义词、调了语序 | 逐字抄，抄不了就注明是转述 |
| 自己打自己 | 正文说 X，附录里说不是 X | 全文搜同源表述，一起改 |

这四条的共同点：**语法上都很顺，只有翻回素材才看得见。** 所以判据里必须有「能翻到哪一行」这一层。

## 交付

**成品直接给用户，不要放目录、不要走流程。** 用户要的是能用的东西。

交付时附三样东西（各一句，不要写长）：

1. 哪些地方是立场句、没有外部来源（不要假装有据）。
2. 哪些地方素材本身有矛盾，你选了哪一边、为什么。
3. 对方最可能追问的那一句，以及你准备好的答法。

## 卡住了怎么写

改到第三轮仍不过 95，**不要继续堆版本，也不要交一份自己知道不够的稿**。写 `blocked.md`：

```markdown
# 卡在 d2（数字可查）
当前：91
缺什么：<具体到哪一句说不出来>
需要你给什么：<一份含 X 的素材 / 一个商业口径的拍板>
不给时我停在：<draft-v3.md，哪一处我做不到>
```

**三次改不动，问题在标准不在稿。** 这时候回去看 `criterion` 是不是自相矛盾、是不是要求了素材里根本没有的东西——改标准，不是继续改稿。

## 这套东西不管什么

| 不管 | 为什么 |
|---|---|
| 教授真当过评委 | 它的专业性来自「没看过稿」+「判据必须可抽查」，不来自身份 |
| 导师和教授会不会串通 | 同一个模型换 prompt，价值观一样；只靠「不许看稿」这一道 |
| 标准会不会被手改 | 导师有写权限；所以要留 `rubric.json` 的时间戳，改过就要重判 |
| 高分 = 真实好评 | 判据只覆盖抽得出来的东西。最终仍要人看一眼 |
