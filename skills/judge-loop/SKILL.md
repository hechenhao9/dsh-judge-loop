# judge-loop：不是打分器，是交付闸门

## 先看这条：默认不跑闸门

**成品直接交给用户。** 教授定细则、导师写到位、稿子交出去——这条主线和 `gate.cjs` 无关，一条命令都不必跑。

`gate.cjs` 只在三种时候用：

1. 用户明确说「机械核对一遍」「跑一遍检查」；
2. 这份东西要发出去、且**错一句的代价很大**（对外提案、合同附件、公开发布）；
3. 你想复现「为什么上一版更好」——`runs/` 里成对的稿与判分记录是唯一能回看的证据。

其余时候跑它就是给交付加时延。上一版它逼出了 8 版修订、几十万 token、最后用户叫停——那是我的用法问题，不是它没价值（它拦下过三次真事：导师伪造外部评审、我把自己认为的满分当满分、为让检查通过而想删掉一版旧稿）。**价值在「该用的时候用对」，不在每轮都跑。**

## 为什么要有两个团队

一份答案能到多少分，上限在**评分细则**，不在写的人。

上一版这个技能最要命的问题：**细则是我自己写的，写之前稿子已经有了。** 我把稿子的四个特征（140–160 词、双斜线标停顿、卖点后跟路径、可整段复制）抄成了四条判据，然后对着自己抄的标准拿 100 分。出题人和考生是同一个人，那个 100 分没有意义。

所以这里把它拆成两个互不隶属的角色：

| 团队 | 干什么 | 不许干什么 |
|---|---|---|
| **教授团队**（`professor`） | 只读题目与素材，产出 `rubric.json`。这一份决定作品上限 | 不许看导师写的任何一版稿；不许在细则里写「参考稿是这样」 |
| **导师团队**（`tutor`） | 按 `rubric.json` 一步做到满分，可向教授**取经** | 不许改 `rubric.json`；不许自己造判据 |

「取经」只允许问三件事：这条的**初衷**是什么、它在防什么、满分的样子长什么样。**不许问「怎么写才能满分」**——那不是取经，那是让教授代写。

## 目录

```
<work>/
  rubric.json                 教授产出（导师不许改；改了 gate 会按新尺子重判，旧分作废）
  runs/<N>/
    task.md                   题目原文 + 用户硬约束（照抄，不许转述）
    draft-v1.md               导师的稿
    score-v1.json             判分（含 quote）
    draft-v2.md               按扣分改后的稿
    score-v2.json
    veto.json                 {"vetoes_hit": []}
    BLOCKED.md                未满分时必须存在
  reviews/r-00001-<hash8>.json  外部判分记录（gate review 写）
  final/                      只有 gate promote 能写
```

## 命令

```bash
gate rubric  <work>                                   # 校验教授产出的 rubric
gate check   <work>                                   # 结构 + 证据是否成立
gate score   <work> <N>                               # 这一轮总分，不满分 exit 3
gate review  <work> <N> <scores.json> --reviewer <self|ID>
gate promote <work>                                   # 只有满分 + 无否决 + 有外部记录才写 final/
gate status  <work>
```

Windows 下 `gate` 就是 `scripts\gate.cmd`（纯 ASCII，三级 node 回退）。**不要用管道调用**——`| more` 会把退出码吞成 0。

| 退出码 | 含义 |
|---|---|
| 0 | 通过 |
| 2 | 结构或判分记录非法 |
| 3 | 不满分 |
| 4 | 命中硬否决 |
| 5 | 缺外部判分记录 |
| 6 | 轮次超限或缺 BLOCKED |
| 7 | 用法错 |
| 8 | rubric 不合法（教授要改的是这个） |

## 双团队协议

### 第一步：教授定细则

起一个 subagent，**prompt 第一行写 `judge-loop role: professor`**，只给它：

- 题目原文（用户怎么问的，一字不改）
- 素材（文件路径，或"只能凭常识"要明说）
- 用户给过的硬约束（字数、语言、交付形态）

**不给它任何稿子。** 它不知道、也不需要知道导师会怎么写。

它的产出是 `<work>/rubric.json`，长度 4–6 维，合计 100。每条维度必须有：

- `criterion`：≥12 字，且**含一个能被外部抽查的对象**（路径 / 文件 / 行号 / 命令 / 退出码 / 原文 / 数字 / 链接）。写「有深度」当场被 gate 判 exit 8。
- `pass_example` / `fail_example`：各 ≥8 字、必须不同。写不出两个具体样子，说明这条判据只是形容词。
- `intent` 与 `vision`：这条在防什么、满分的样子长什么样。**导师就是靠这两行取经的。**
- `weight`：10–30。

外加 `vetoes` 至少 1 条，每条要有 `why`（说不出「为什么不能用分数换」，这条否决守不住）。

产出后立刻 `gate rubric <work>`，exit 8 就回炉——**别带着坏尺子往下走**。

### 第二步：导师取经

导师拿到 rubric 后，先把每一维翻译成一句「这份稿里一定会出现的话」：

| 判据 | 它在稿里长成哪句 |
|---|---|
| 说清机制 | 「因为它每次写入都带前一条的 hash，所以删中间那条就对不上」 |
| 数字有出处 | 「281,023 行（`精华企业库.csv`，185.1 MB）」 |

写不出来 → 用 `subagent` 问教授：**「维度 d2 的初衷是什么？你在防哪种稿？」** 教授的回答只用来理解，不抄进稿子。

### 第三步：一步到位地写

「一步到位」不是不许改，是**交付的那一刻必须是满分**。所以：

1. 按权重从高到低写，每维先造出那句会被引用的话，再连成文。
2. `score-v1.json` 自评：每维只给 0/4/7/10，`quote` 抄稿里逐字存在的 ≥12 字段落。
3. 有维度不满分 → 每条扣分必须写成 `把 draft-v1.md:63 的「原文≥12字」改成「新句」`。写不出这个句式，说明你只知道不满意、不知道改哪句。
4. 改出 `draft-v2.md`，**至少删掉一处**（只加不减的改法会让稿子越长越像 AI）。
5. `score-v2.json` 满分的话必须带 `beyond_spec`：至少一条「原需求没要求、但对用户下一步有实际作用」的增量，`what` 要在稿里能找到，`reason` 写清「他为什么没想到」。

### 第四步：外部判分（这一条不许自己给自己盖章）

```bash
gate review <work> 2 runs/2/score-v2.json --reviewer subagent-<id>
```

`--reviewer` 必须是造这份 `score-v2.json` 的那个独立 subagent 的标识，不是 `self`。**满分没有非 self 的记录，`promote` 一律 exit 2/5。**

### 第五步：放行

```bash
gate promote <work>
```

三个条件同时成立才写 `final/`：总分 100、否决 0 条、外部记录里的 `draft_sha256` 等于当前稿。少一个都 exit ≠ 0。

**用户只看 `final/`。** 把稿子直接贴进对话 = 绕过闸门。

## 卡住了怎么办

轮次上限 5。第 5 轮还没满分，不许硬凑，也不许交稿——交 `runs/<N>/BLOCKED.md`：

```markdown
# 卡在 d2（数字可查）
当前总分：92.5
缺什么：<具体到某一句话说不出来>
需要你给什么：<一份含 X 的素材 / 一个商业口径的拍板>
你不给时我停在：<停在 draft-v5.md，不进 final/>
```

这是阻塞上报，不是交付。`gate promote` 在缺 BLOCKED 时 exit 6，所以这条路也堵不住你骗自己。

## 这套东西堵不住什么

| 缺口 | 为什么 | 现在的处理 |
|---|---|---|
| 教授也是模型 | 它的专业性来自「没看过稿」+「判据必须可抽查」，不来自它真当过评委 | 判据里含路径/数字/引文，才允许过 |
| 导师和教授可能串通 | 同一个模型换个 prompt，价值观一样 | 只靠「不许看稿」+ 外部 reviewer 不是 self |
| `rubric.json` 可以被手改 | 导师有写权限 | 改了 gate 按新尺子重判，旧 `score-*.json` 的 `quote` 与 `total` 会立刻对不上，exit 2 |
| 高分与真实好评不是一回事 | 判据只覆盖抽得出来的东西 | `beyond_spec` 逼你交一条判据外的增量；最终仍要人看 |

## 人的部分

机器只判得了「引文在不在、数字对不对、记录全不全」。三件事仍要人做：

1. **给教授题目时别泄漏你想看到什么。** 一句「记得突出 AI」就把上限锁死了。
2. **看 `beyond_spec` 那条是不是真的有用**，还是为了凑分编的场面话。
3. **抽一维要求引原文**：让它指出 `draft-v2.md` 第几行，你去翻。
