# 导师：按标准写，不按感觉写

## 你手上只有这些

- `<work>/runs/<N>/task.md`：题目与用户硬约束（照抄的，不许转述）
- `<work>/rubric.json`：教授给的判据
- 素材文件

**你不能改 `rubric.json`。** 觉得某条判据不合理，去找教授问它的初衷；改尺子等于自己给自己出题，上一版就是这么废掉的。

## 第一步：把判据翻译成句子

写稿之前先填这张表，填不出来说明你还没读懂判据：

| 维度 | 这条判据要求稿里出现的那一句 | 它会落在第几节 |
|---|---|---|
| d1 机制（30） | 「因为它每次写入都带前一条的 hash，所以删中间那条就对不上」 | §二 记录只增 |
| d2 证据（25） | 「281,023 行（`精华企业库.csv`，185.1 MB，38 列）」 | §三 数据来源 |

**两维共用同一句 = 有一维没做到。** 一句能同时满足两条判据，通常说明其中一条写得不够具体。

写不出来就去问教授（见下），不要在稿里塞「深度」「逻辑」「价值」这类词来凑。

## 第二步：先造证据句，再连成文

顺序反了就会变成「先写一段漂亮话，再想办法证明它」——那是上一版反复被打回的原因。

1. 按权重从高到低，把上表每一行写成一句具体的话（带路径、数字、引文、命令）。
2. 每句打个 tag 标它服务哪一维。
3. **最后**才做通顺化。通顺化只许调整连接与删冗余，不许动证据本身。

## 第三步：自评（`score-v1.json`）

只给四档：**0 / 4 / 7 / 10**。不许给 8、9——那是在回避判断。

```json
{
  "round": 1,
  "total": 92.5,
  "dims": [
    {
      "id": "d1",
      "score": 10,
      "quote": "从 draft-v1.md 里逐字抄一段 ≥12 字的原文",
      "deductions": []
    },
    {
      "id": "d2",
      "score": 7,
      "quote": "逐字抄一段 ≥12 字",
      "deductions": [
        { "fix": "把 draft-v1.md:63 的「这个数字大约是二十八万条」改成「281,023 行（精华企业库.csv，185.1 MB，38 列）」" }
      ]
    }
  ],
  "beyond_spec": []
}
```

三条硬规矩，脚本逐条判：

1. **`quote` 必须逐字出现在那版稿里**（≥12 字）。抄不出来 = 你其实没读到那一维。
2. **不满分就必须有 `deductions`**，且每条 `fix` 必须写成 `把 draft-vX.md:NN 的「原文≥12字」改成「新句」`。写「深度不足」「可以更清楚」= 你只知道不满意，不知道改哪句。
3. **`total` 是脚本按 rubric 权重重算的**，你写的数只要差 0.001 就 exit 2。

一维从 10 掉到 7，总分 = 100 − 3w/10。**w=30 时掉到 91，不可能靠别处补回来。** 所以每一维都得是 10。

## 第四步：改（`draft-v2.md`）

- 只动 `deductions` 点到的句子。
- **至少删掉一处。** 只加不减会让稿子越长越像 AI，也让你不敢承认原来那句是废话。
- 改完重新填 `score-v2.json`，quote 从 **v2** 里抄。

## 第五步：`beyond_spec`（这才是「超出细则」）

满分之后还必须有增量，否则只是「刚好卡线」。三条里至少挑一条真做：

| 类型 | 例子 |
|---|---|
| 执行路径 | 「下周一你先做这三步，第一步是拍那张证」 |
| 可复用件 | 「这段话术你可以直接复制发给对方」 |
| 预答 | 「他会追问 X，答案在第三节最后一句」 |

要求：

- `what` 里的内容要能在稿里 `indexOf` 到（不是空口说做了）
- `reason` 写清「他为什么没想到 / 为什么这条判据覆盖不到」

**不许为了凑 beyond_spec 加废话。** 判据外的增量如果对下一步没用，就是不达标。

## 第六步：请外部判分

```bash
gate review <work> 2 runs/2/score-v2.json --reviewer subagent-<那个独立 subagent 的 id>
```

这个 reviewer 必须是**真的独立跑过一遍**的人（另一个 subagent），不是 `self`。它只做一件事：逐维去稿里找那句 quote，找不到就给 0。

- 找不到 → 那一维是空的，回第一步
- 找到但意思对不上 → 判据与内容错位，去找教授问初衷

## 第七步：放行

```bash
gate promote <work>
```

非 0 就不许交。0 才写 `final/`。

## 卡住了：交 BLOCKED.md，不交稿

五轮还没满分，写 `runs/<N>/BLOCKED.md`：

```markdown
# 卡在 d2（数字可查）
当前总分：92.5
缺什么：素材里没有 2024 年的产能数字，我不能编
需要你给什么：一份含产能的文件，或一句「这个数可以不写」
你不给时我停在：draft-v5.md，不进 final/
```

**这是唯一被允许的「未完成交付」**，而且它不是交付——是问人。

## 不要做的四件事

1. **不要改 rubric。** 改了旧分立刻作废。
2. **不要自己给自己 `--reviewer self` 然后当外部记录。** promote 会 exit 2/5。
3. **不要在稿里写「如上所述」「综上所述」这类话充数。** 判据抽不出来，只会拉低 d1。
4. **不要先写稿再回头把稿的特征写成判据。** 那是上一版失败的原因，教授的职责正是防这个。
